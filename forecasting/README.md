# Corrected prescription forecasting study

The [educational notebook](<../Forecasting of Antidiabetic Drug Prescriptions - Corrected.ipynb>) accompanies the untouched [historical notebook](<../Forecasting of Antidiabetic Drug Prescriptions.ipynb>). The [runner](corrected_forecast.py) performs the complete corrected calculation using Python's standard library. [Results](corrected_results.json) and the [forecast plot](rolling_forecasts.svg) were generated by running it with Python 3.14.5. The notebook's code cells were also run sequentially with Python as a smoke check; no Jupyter kernel or saved cell outputs were used.

## Data and reproduction

The exact dataset is Marco Peixeiro's [`AusAntidiabeticDrug.csv`](https://github.com/marcopeix/TimeSeriesForecastingInPython/blob/master/data/AusAntidiabeticDrug.csv) from the [*Time Series Forecasting in Python* companion repository](https://github.com/marcopeix/TimeSeriesForecastingInPython), which displays an [Apache 2.0 license](https://github.com/marcopeix/TimeSeriesForecastingInPython/blob/master/LICENSE.txt). It is a 4,621-byte CSV with 204 monthly `ds,y` rows (July 1991–June 2008). The CSV is deliberately excluded by this repository's existing `*.csv` ignore rule; the runner will not download it automatically.

1. Download only that source file and save it as `forecasting/AusAntidiabeticDrug.csv`. On PowerShell:

   ```powershell
   Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/marcopeix/TimeSeriesForecastingInPython/master/data/AusAntidiabeticDrug.csv' -OutFile 'forecasting/AusAntidiabeticDrug.csv'
   ```

2. Confirm SHA-256 `d6f32528dbeabdad405b578d351375aca9eb6f0eee7b632c9a49b909f80741c5`. The runner verifies this before fitting.
3. From the repository root run `python forecasting/corrected_forecast.py`.
4. Run `python -m unittest discover -s forecasting -p 'test_*.py' -v` for focused checks.

No dependency installation or random sampling is required. The analysis is deterministic. `corrected_results.json` records the actual 36 holdout values, each forecast and each origin's errors. Re-running the script recreates it and the SVG.

## Protocol and newly calculated results

The first 168 months select one model by conditional Gaussian AIC from `SARIMA(p,1,0)(0,1,0)[12]`, `p=0,1,2`, with an intercept in the differenced equation. All candidates use the same 153 transformed training observations. The selected `p=2` is refitted at origins 168, 180 and 192 to predict the next 12 months. Ordinary naive and seasonal naive use the same available history and forecast targets. Model selection never inspects the final 36 months.

| 36-month rolling holdout | MAE | RMSE | MAPE |
| --- | ---: | ---: | ---: |
| Ordinary naive | 3.178 | 4.148 | 14.545% |
| Seasonal naive | 2.658 | 3.154 | 12.687% |
| Selected conditional SARIMA | **1.795** | **2.156** | **8.869%** |

These values are freshly calculated by the runner on the named source snapshot. The historical 7.899% MAPE belongs to a different model and remains a saved notebook result only. The model's lower error on three annual forecast windows does not establish expected accuracy on future data. Conditional AIC rankings here are valid only within the fixed transformation, Gaussian likelihood convention and common 153-row sample. Their values cannot be compared numerically with the original statsmodels AIC.

## Historical lessons and remaining limits

The original notebook's `np.diff(y_diff, n=12)` is a twelfth-order adjacent difference applied after one ordinary difference, rather than a lag-12 seasonal difference. Its STL/ADF analysis uses the full series before the split. Its saved sorted AIC first row disagrees with the narrative model and later fitted AIC; the record does not identify why. Its claim that SARIMAX cannot be used without exogenous features is also too strong: the statsmodels class supports an endogenous-only seasonal ARIMA model. Nonrejection by Ljung–Box does not prove residual independence. The original notebook and all its output remain preserved as historical learning.

This corrected study uses a restricted conditional least-squares model, with no seasonal AR/MA terms, exact-likelihood fit, calibrated intervals, or prospective validation. A valuable next step is a pinned statsmodels environment and a small, predeclared exact-likelihood comparison under the same three-origin protocol, including forecast-interval coverage.
